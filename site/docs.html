Settings FAQ

Install

Typed Graph works on desktop and mobile. Pick one:

  • Community plugins (recommended): open Typed Graph in Obsidian, or go to Settings → Community plugins → Browse → Typed Graph → Install → Enable. Directory page: community.obsidian.md/plugins/typed-graph.
  • BRAT, for beta builds: install Obsidian42 - BRAT, run BRAT: Add a beta plugin and enter Volland/obsigraph.
  • Manual: from the latest release copy main.js, manifest.json and styles.css into <vault>/.obsidian/plugins/typed-graph/, reload, enable.

VS Code extension

Without Obsidian, the TypeGraph extension shows typed backlinks and the graph for the markdown and @lat:/@tg:-annotated code in a workspace, and offers to run tg init. It is published on Open VSX as pavlyshyn.typegraph-vscode.

  • VSCodium, Cursor, Windsurf, Gitpod, Theia (editors that use Open VSX): search TypeGraph in the Extensions view and install, or run codium --install-extension pavlyshyn.typegraph-vscode.
  • VS Code: download the .vsix from the Open VSX page and run Extensions: Install from VSIX…, or code --install-extension typegraph-vscode-<version>.vsix.
  • From source: npm install && npm run package:vscode builds packages/vscode/typegraph.vsix.

Settings: typegraph.roots (folders that form the graph, default ["."]) and typegraph.ignore (folder names to skip, default ["node_modules"]).

New to typed graphs? Download the demo vault, unzip it and open the folder as a vault (Open folder as vault). The plugin comes preinstalled; turn on community plugins when Obsidian asks, then open Start Here. It uses every feature and includes a hands-on Cypher manual with live examples.

Quick start

  1. Give a note a type: add type: Person to its frontmatter.
  2. Write an edge line: knows:: [[Bob]] {since: 2020}.
  3. Add a query block anywhere: 
    ```graph-query
MATCH (a:Person)-[r:knows]->(b)
RETURN a, r, b
```
  4. Open the explorer with Typed Graph: Open graph view or the ribbon icon.

Edges

An edge is one line in a note; the note is the source.

knows:: [[Bob]]
knows:: [[Carol]] {since: 2018, label: "met at conf"}
-distrusts:: [[Eve]]
+trusts:: [[Bob]]
- works_at:: [[Acme]], [[Initech]] {role: engineer}
PartMeaning
type::Edge type. Graph Link Types lines work unchanged.
- / + prefixSign: −1 or +1 (default +1). weight is an ordinary property.
{…}Properties: numbers, booleans, quoted or bare strings, lists.
{id: "…"}Pins the edge id; otherwise it is source#type#target#n.
headingThe nearest heading above is recorded with the edge.

Lines in code blocks and frontmatter are ignored. Malformed property blocks keep the edge and appear in Show diagnostics. Links to missing notes become faded stub nodes.

Typed nodes

Every note is a node. Frontmatter type becomes its labels; a list gives several:

---
type: [Person, Employee]
age: 40
---

Frontmatter fields, title and path are node properties.

Schema notes

Notes directly in Types/ (configurable) declare types. schema: describes the type named by the note's title, and its body is that type's template:

---
schema:
  properties:
    status: {kind: text, default: active, values: [active, alumni]}
    born: {kind: date, required: true}
    aliases: list
  edges: {knows: Person, worksAt: Company}
  visualization:
    color: "#7c5cff"
    shape: ellipse
    icon: user
    label: name
    edges:
      knows: {color: orange, line: dotted}
---
## Notes

One note can also describe a whole subsystem: several types under schemas: and edge types with their own properties under edgeTypes:.

---
schemas:
  Person: {properties: {email: {required: true}}, edges: {worksAt: Company}}
  Company: {uri: schema:Organization, properties: {founded: date}}
edgeTypes:
  worksAt:
    from: Person
    to: Company
    properties: {since: date, role: {values: [engineer, manager]}}
    visualization: {color: green}
---
  • Kinds: text, number, boolean, date, datetime, link, list. Properties take required, many, values, default and uri.
  • edges is a list of allowed outgoing edge types, or a map to target types (worksAt: Company) or to {target, many, required}. Omit it to allow any edge.
  • uri accepts an IRI or a CURIE such as schema:Person; add prefixes with a prefixes: key.
  • Create note from type uses the template note if set, else the schema: note's body, else a template generated from the schema. It never overwrites a note.
  • Validation is advisory: required and allowed values, lists, allowed, required and single edges, edge endpoints and edge properties. Issues show in the status bar and Show diagnostics.
  • Export schemas as SHACL and Import SHACL shapes exchange schemas with RDF tools, as do tg schema export and tg schema import.

The format is an open specification, Typed Graph Schema (TGS) 0.1, with a JSON Schema and conformance examples.

Edge property embeds

We met in {{edge: Alice -knows-> Bob . since}}.
{{edge: met-2020 . since}}
{{edge: met-2020}}

Find an edge by endpoints and type or by pinned id; . property shows one value, otherwise a small table. Put a sign before the type to require it: --distrusts-> (negative), -+knows-> (positive). Embeds referencing unpinned edges get a diagnostic suggesting an id.

Query blocks

A graph-query block is an optional header, a blank line, then the query.

```graph-query
view: table
columns: who, since
backend: builtin
node.Person: color=#e5484d, shape=hexagon
edge.knows: line=dashed

MATCH (a:Person)-[r:knows]->(b)
RETURN a.title AS who, r.since AS since
```
OptionValues
viewauto (graph when the result has nodes, relationships or paths), table, graph
columnsTable columns to show, in order
heightGraph height in pixels (100–4000)
backendbuiltin or ladybug (needs the sidecar)
node.<Type> / edge.<type>Style overrides for this block

Results refresh live. Graphs larger than the element limit fall back to a table.

openCypher subset

  • Clauses: MATCH, OPTIONAL MATCH, WHERE, WITH, RETURN [DISTINCT], ORDER BY, SKIP, LIMIT.
  • Patterns: labels, property maps, -> <- -, [:a|b], [:knows*1..3], p = (...).
  • Aggregates: count(*), count, sum, avg, min, max, collect (with DISTINCT).
  • Functions: id type labels keys properties startNode endNode length nodes relationships toLower toUpper trim replace substring split left right size coalesce toString toInteger toFloat abs round floor ceil sign head last reverse.
  • Built-ins: n.stub, n.title, n.path, r.id, r.sign.
Queries are read-only. CREATE, SET, DELETE, MERGE and REMOVE are rejected. UNWIND, UNION, CALL, CASE and =~ are not in the built-in subset; use backend: ladybug for those.

Styling

Every attribute resolves on its own; the most specific source wins:

  1. Block header (node.Person: color=red)
  2. Schema note visualization
  3. Settings → Type styles / Edge styles
  4. Defaults: a stable color per type; negative edges dashed red with a tee arrow

Node attributes: color, shape (ellipse, rectangle, round-rectangle, diamond, hexagon, triangle, star), icon (Lucide name), label (property shown instead of the title). Edge attributes: color, line (solid, dashed, dotted).

Graph view

  • Empty query: follows the active note's neighborhood.
  • Enter a query and press Run or ⌘/Ctrl+Enter.
  • Right-click or long-press a node to expand it; double-click or ⌘/Ctrl-click to open its note.
  • Select a node or edge to see its properties and where each style came from.

This is a separate view. Obsidian's core Graph view is left untouched, because it has no plugin API and patching it breaks on Obsidian updates. It still draws one plain line per linked pair of notes, with no edge types, signs or properties.

Color types in the core Graph view

You can still color nodes by type in the core Graph view, without any plugin code. Open the core Graph view, expand Groups, choose New group, and enter a property search such as [type:Person], then pick a color. Add one group per type. The first matching group wins, so order groups from most to least specific.

The sidecar

An optional headless Node service over a read-only copy of your vault. It powers the Ladybug backend, vector search, GraphRAG and MCP.

npm install && npm run build:sidecar
OBSIGRAPH_VAULT=/path/to/vault OBSIGRAPH_DATA=/path/to/data OBSIGRAPH_TOKEN=change-me \
  node packages/sidecar/dist/server.mjs

Docker: packages/sidecar/Dockerfile and compose.example.yaml mount the vault :ro, run as non-root and publish on host loopback only.

Ladybug backend

The sidecar mirrors the graph one-way into LadybugDB. Set the sidecar URL and token in plugin settings, then use backend: ladybug in a block. Queries the built-in parser reads are translated so they return the same results. A 52-query conformance suite keeps the two engines in agreement.

Other read Cypher (UNWIND, CASE, UNION, =~) runs on LadybugDB untranslated, against the mirror layout. The result carries a notice saying so. In that layout:

  • Every note is a Node, with title, path, stub and a labels list.
  • Each edge type is its own relationship table.
  • Properties are typed columns named p_<name>_<kind>. The kind is s (text), n (number), b (boolean), ls or ln (lists) or j (anything else).
```graph-query
backend: ladybug
view: table

MATCH (p:Node)-[c:contributes]->(proj:Node)
WHERE list_contains(p.labels, "Person")
RETURN p.title AS person, proj.title AS project,
       CASE WHEN c.p_hours_n >= 100 THEN "core" ELSE "helper" END AS involvement
```

Vector search

Notes are chunked by heading with title, type and frontmatter as context; each edge becomes a sentence like Alice (Person) knows Bob (Person) - met at NeurIPS. Embeddings come from local Ollama by default.

POST /search
{"query": "machine learning", "target": "nodes", "k": 5, "types": ["Person"],
 "then": "MATCH (p)-[:works_at]->(c) WHERE id(p) IN $hits RETURN c.title"}

GraphRAG

POST /retrieve
{"question": "Who works with Alice on search?", "k": 5, "depth": 1}

Returns the best chunks of the vector hits and of their graph neighbors (hits first, then by distance), each with path, heading, score and role, plus the connecting edges. Hub expansion is capped and flagged.

MCP for agents

claude mcp add typed-graph \
  -e OBSIGRAPH_VAULT=/path/to/vault -e OBSIGRAPH_DATA=/path/to/data \
  -- node /path/to/packages/sidecar/dist/server.mjs --stdio

Tools: cypher_query, vector_search, graphrag_retrieve — all read-only. Over HTTP use POST /mcp with the bearer token.

Security

  • The vault is never written: mounted read-only, with every write confined to the data directory.
  • Bearer token on everything but /health; loopback bind by default; body and time limits.
  • Read-only queries enforced twice on Ladybug: a guard and a read-only database snapshot.
  • Retrieved note text is marked as untrusted content for agents.

CLI: tg

tg works on a lat.md/ folder, the same format as lat.md. Install with npm install -g @typedgraph/cli. It finds the project by walking up to the nearest lat.md/ or .tg/ folder; --dir overrides. Exit codes: 0 ok, 1 findings, 2 usage or internal error. --json prints machine-readable output on read commands.

tg check [md|code-refs|index|sections]Validate links (including source files and symbols), @lat: and @tg: references, require-code-mention coverage, directory index files and the 250-character leading-paragraph rule.
tg locate <query>Find sections by id, short id or fuzzy name.
tg section <query>Show a section with its links, what references it and the code that does.
tg refs [--scope md|code|md+code] <query>Sections and code that reference a section.
tg expand <text>Replace [[refs]] in text with full ids and locations.
tg search [--limit n] [--lexical] <query>Lexical ranking by default. With TG_EMBED_PROVIDER=ollama|openai or a key (TG_EMBED_KEY, or LAT_LLM_KEY) it fuses lexical and vector ranks. TG_EMBED_URL and TG_EMBED_MODEL pick the endpoint and model. Vectors are cached in .tg/; tg reindex rebuilds them.
tg cypher [--code off|annotated|all] <query>Read-only openCypher over the section graph: Section nodes (section, title, file, depth, summary), contains and references edges, and with --code CodeFile and CodeSymbol nodes. Pattern predicates such as WHERE NOT ()-[:x]->(s) are not supported; use OPTIONAL MATCH with a count.
tg edges [--type t] [--to s] [--file f]List annotation edges from code to sections.
tg gen <target>Print agents.md, claude.md, cursor-rules.md, skill.md or graph-skill.md.
tg init, tg hook, tg mcpSee Agents and hooks.
tg export, tg import, tg schemaSee Export and import.
tg okf check [dir]Check any folder against Open Knowledge Format v0.2 conformance: concepts need parseable frontmatter with a string type, index files no frontmatter (except okf_version at the root), log date headings YYYY-MM-DD. Broken links, wikilinks and missing descriptions are warnings. Exit 1 only on errors.

Annotations in code

Two comment forms link code to docs, in //, # and block comments:

// @lat: [[auth#Token expiry]]                       a plain reference
// @tg: implements:: [[auth#Token expiry]] {since: 2}   a typed edge
// @tg: -contradicts:: [[design#Stateless sessions]]    a negative edge
// @tg: implements:: [[a#X]], tests:: [[b#Y]]           several edges
// @tg: [[a#X]]                                         same as @lat:

@lat: follows lat.md's exact pattern (a // or # comment and one link). @tg: uses the same type:: [[Target]] {props} grammar as notes, so signs, properties and several edges work as they do there. The edge starts at the declaration that follows the comment within three lines (a class member is Class#member); otherwise it belongs to the file and tg check warns. A schema note's edges list gives advisory checks on edge types.

Source links in docs, [[src/server.ts#App#listen]], are checked against the file. Supported: TypeScript and JavaScript (.ts .tsx .js .jsx .mts .cts .mjs .cjs), Python, Go, Rust and C (.c .h). Symbols are found with regex finders, so a file whose strings or braces do not balance, or a class written on one line, is reported as "cannot tell" and never as a missing symbol.

Code in the graph

Source files and symbols can appear as derived CodeFile and CodeSymbol nodes, keyed by path and path#Class#method, with contains edges and the annotation edges. They are built in memory and never written to disk or to your vault.

  • Modes. off (the plugin default), annotated (the CLI default: annotated symbols, what annotations point at, and their files) and all. In the CLI use --code or TG_CODE.
  • In Obsidian. Settings → Code in the graph and Code folder, or the Code dropdown in the Graph view. A graph-query header line code: hide removes code nodes from one block. Code nodes have their own shapes and colors, below any style you configure.
  • Links agree with nodes. [[src/auth.ts#login]] in a note ends at the CodeSymbol node, never at a stub.

Agents and hooks

  • tg init [--agent claude|agents|cursor] [--write] [--migrate] prints a diff of every file it would create or change and writes only with --write. For Claude Code that is the CLAUDE.md block (between %% tg:begin %% markers), hooks in .claude/settings.json, the tg entry in .mcp.json and two skills, tg-docs and tg-graph. An existing lat.md block is replaced only with --migrate, which also swaps the lat hook commands and the lat MCP entry.
  • tg hook claude UserPromptSubmit|Stop and tg hook cursor stop are called by the agent. The prompt hook reminds it to search first, expands [[refs]] in your prompt and adds the top lexical hits. The stop hook blocks finishing when tg check fails or five or more code lines changed with little change in lat.md/. Hooks always exit 0.
  • tg mcp serves tg_locate, tg_section, tg_search, tg_expand, tg_check, tg_refs, tg_cypher and tg_edges over stdio: claude mcp add tg -- tg mcp.

Export and import

  • tg export <out> [--vault dir] [--folder sub] [--force] writes vault notes under <out>/lat.md/. Typed edges become type: [[link]], property blocks are dropped, {{edge: …}} embeds become their value, notes get a level-1 heading and directory index files if missing, and links to notes outside the export become plain text. It then runs the normal check and prints a loss report. Round trips are not guaranteed. It refuses a non-empty target without --force.
  • tg export <out> --format okf [--default-type T] [--title T] writes an Open Knowledge Format bundle at <out>/ instead. Wikilinks become bundle-absolute markdown links, and typed edge lines keep their type, sign and properties (knows:: [Bob](/People/Bob.md) {since: 2020}), so Typed Graph reads the bundle back into the same graph. Every concept gets a string type (default Note), plus a title and description if missing. Notes named index.md or log.md are renamed, embedded attachments are copied, and every folder gets an index.md. The command prints a change report and verifies the result with tg okf check.
  • tg import <path> [--mount] [--into name] copies a lat.md/ folder (or the one inside a project) into the current vault or project, or symlinks it with --mount. It refuses a non-empty destination and never changes the source.
  • tg schema export <out.ttl> [--vault dir] [--schema-folder Types] [--base iri] writes every type and edge type in the schema folder as W3C SHACL shapes in Turtle, following the TGS mapping. The output is deterministic, so it diffs cleanly.
  • tg schema import <file.ttl> [--layout auto|per-type|single] [--into name] [--force] turns SHACL shapes into schema notes: one note per type by default, or all of them in one note. It rewrites only the schema keys of existing notes, leaves alone notes that also declare types missing from the file (unless --force), and prints a drop report of SHACL features outside the TGS subset.

In Obsidian, notes under a lat.md/ folder get working [[file#Heading#Sub]] links and show link and section problems in the diagnostics list. Files are not modified.

FAQ

Does it change my notes?

No. The plugin and the sidecar only read notes. Only Create note from type, Create schema note and Import SHACL shapes write files, on request; the import changes only the schema keys of notes in the schema folder.

Do I need Graph Link Types or Dataview?

No. Typed Graph reads the same type:: [[Target]] lines on its own.

Does my vault leave my machine?

Not by default. Embeddings use local Ollama; a hosted endpoint is only used if you configure one.
